## September 9 product update

- A two-step new-check flow separates fictional examples from controlled real inquiries, collects the intended transaction, and opens editable requirements before case creation. Home example cards remain one-click demonstrations.
- Purchase checks use purchase total and a collection window. Rental-only deposit and up-front-cash fields are removed. Returning to rental restores those requirements. Switching the transaction never converts prior evidence into a matching purchase/rental answer.
- Exact-item requirements accept up to three named alternatives. Identity matching, source scope, price and availability stay separate. Removing an alternative recalculates the verdict and earlier revisions remain unchanged.
- Reviewed edits survive moving back within onboarding and an API create failure. Mobile editing uses full-width fields. Invalid fields explain why save is disabled.
- `npm run live:check` reads local setup and registered account IDs without network access, phone calls, or printing private credentials/recipient details. Invalid numeric settings or calling windows prevent live dispatch. Midnight is now a valid start hour.
- The CALL-E HTTP adapter has direct no-network contract tests in addition to orchestration fault tests. Malformed transcript entries become invalid output instead of crashing reconciliation. Evaluator and schema versions are 1.1.0.

## Deliberate limits and remaining work

- **Live proof:** run at least three contrasting consenting tests using `LIVE_TEST_PROTOCOL.md`. Verify real create/read shape, metadata availability, recipient output, provider retries, costs and retention. Current tests make no telephone calls.
- **Input coverage:** the item template now supports purchase and rental, plus up to three explicitly accepted alternative models. Transaction changes invalidate mismatched evidence; an alternative needs its own price/availability evidence. A general AI intake model remains unimplemented: the bounded starter helper requires explicit field review. Custom subjective judgments remain manual.
- **Candidate sourcing:** samples use fictional curated candidates; live mode uses operator-configured consenting recipients. Public discovery and arbitrary user-entered phone dispatch are not enabled.
- **Recorded evidence:** the data model preserves provenance and original source times, but there is no user-facing historical recording import workflow. A saved live result stays live provenance and expires normally.
- **Evaluation study:** 30 development and 15 designated held-out scenarios are self-authored. Independent labeling, comparison with a plain-summary baseline, aggregate evidence-support measurement, active-user-time instrumentation and real recipient/cost measurements remain outstanding. Do not describe fixture results as general extraction accuracy.
- **Operational scope:** single persistent Node process with SQLite; local accounts without email verification/recovery; application call-count limits rather than a verified monetary ceiling. Broader deployment needs the corresponding operational work. The Docker image and local backup/restore drill passed; scheduled off-site backups and hosted resilience remain unverified.
- **Hackathon delivery:** choose a contribution license, review the locally staged and validated package, open the public PR, host judge access, capture genuine CALL-E runtime evidence, publish the under-three-minute video and submit. No entry has been published or submitted.
- **Product validation:** user usefulness, repeat usage, pricing and name availability remain unvalidated. Public discovery, shared cases, recurring checks, additional languages and payments are outside this MVP.
